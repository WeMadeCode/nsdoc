# 个人笔记 iOS 产品需求文档

## 1. 文档信息

- 产品名称：一页
- 产品形态：iOS 个人笔记应用
- 文档版本：v0.1
- 更新时间：2026-05-17
- 当前阶段：MVP 需求整理

## 2. 产品概述

本产品是一款面向个人用户的 iOS 笔记软件，强调轻量、私密、可靠和高质量富文本编辑体验。

产品不建设自有账号系统、自有登录体系和自有云端存储。用户无需在 App 内登录，应用只依赖系统层 Apple ID 与 CloudKit 完成数据存储、同步与备份。

富文本编辑页面采用 React + Tiptap 实现，并嵌入 iOS 原生应用中。iOS 侧负责应用框架、数据存储、CloudKit 同步、列表与统计等原生体验；Web 编辑器侧负责复杂富文本编辑能力。

## 3. 产品目标

### 3.1 MVP 目标

- 用户无需登录即可进入应用。
- 用户可以创建、编辑、保存和查看个人笔记。
- 笔记内容支持基础富文本编辑能力。
- 笔记数据存储在 CloudKit，可在同一 Apple ID 设备之间同步。
- 应用在离线状态下可继续查看和编辑本地已有笔记，并在网络恢复后同步。
- 用户明确感知数据属于自己，不上传到产品方服务器。

### 3.2 非目标

- MVP 不建设团队协作、共享笔记或多人编辑能力。
- MVP 不建设产品方后台、管理系统或自有云同步服务。
- MVP 不提供 App 内账号系统，不接入 Sign in with Apple、手机号、邮箱或其他第三方登录。
- MVP 仅支持 iPhone，不支持 iPad、Android、Web 独立版或桌面端。
- MVP 不实现复杂知识库能力，例如双链、图谱、数据库视图。

## 4. 目标用户

### 4.1 核心用户

- 使用 iPhone 记录日常想法、工作笔记、学习摘录和备忘的个人用户。
- 重视隐私，不希望笔记内容存储在第三方服务器的用户。
- 希望拥有比系统备忘录更强编辑能力，但又不想使用过重知识库工具的用户。

### 4.2 使用场景

- 快速记录临时想法、灵感、待办和会议要点。
- 整理长文、读书摘录、学习笔记。
- 按日期回顾自己写过的内容。
- 在多台 Apple 设备之间同步个人笔记。

## 5. 核心原则

- 隐私优先：笔记内容默认只存在用户设备和 CloudKit 中。
- 本地优先：编辑体验不依赖实时网络。
- 轻量快速：打开应用、进入编辑、保存笔记都应尽量少打断。
- 原生体验：列表、导航、CloudKit 状态等能力优先遵循 iOS 平台习惯。
- 专注编辑：编辑器以稳定、易用、内容安全为第一优先级。

## 6. 功能需求

### 6.1 免登录与 CloudKit 状态

### 6.1.1 免登录

用户首次打开应用时，不需要进行 App 内登录。应用直接进入主界面，并检查系统 Apple ID 与 CloudKit 是否可用。

需求：

- 不提供 App 内登录、注册、退出登录流程。
- 不接入 Sign in with Apple 作为产品账号登录。
- 首次打开应用直接进入笔记列表。
- 应用启动后检查系统 Apple ID 与 CloudKit 可用状态。
- 当 CloudKit 不可用时，允许用户继续使用本地笔记能力，并提示同步不可用。
- MVP 阶段不提供手机号、邮箱、微信或其他第三方登录方式。

验收标准：

- 新用户打开 App 后可以直接进入笔记列表。
- 用户无需完成任何 App 内登录即可创建和编辑本地笔记。
- CloudKit 不可用时应用不会卡死或进入异常空白页。
- CloudKit 可用时，笔记可以通过 CloudKit 同步。

### 6.2 CloudKit 数据存储与同步

### 6.2.1 数据存储位置

笔记数据全部存储在 CloudKit 中，产品方不保存用户笔记内容。

需求：

- 应用使用 CloudKit 保存和同步笔记数据。
- 本地应保留可用缓存，使用户离线时仍可访问已同步或已创建的笔记。
- 用户未登录系统 Apple ID、CloudKit 空间不足、CloudKit 不可用时，应提示当前同步状态。
- 本地数据与 CloudKit 数据同步时，应尽量避免用户手动处理技术细节。

验收标准：

- 用户在同一 Apple ID 且 CloudKit 可用的 iPhone 上可以看到同步后的笔记。
- 关闭网络后，用户仍可编辑本地已有笔记。
- 网络恢复后，本地编辑内容可以继续同步。

### 6.2.2 同步状态

需求：

- 笔记保存后应有本地保存成功状态。
- 当 CloudKit 同步存在异常时，应在适当位置提示用户。
- 同步状态提示应克制，不干扰用户写作。

建议状态：

- 已保存
- 正在同步
- 已同步
- CloudKit 不可用
- 同步失败

### 6.3 笔记列表

### 6.3.1 列表展示

用户进入应用后默认看到笔记列表。

需求：

- 按更新时间倒序展示笔记。
- 每条笔记展示标题、摘要、创建时间或更新时间。
- 空列表时展示轻量空状态，并提供创建入口。
- 支持点击笔记进入编辑页面。

验收标准：

- 新建笔记保存后出现在列表中。
- 修改旧笔记后，该笔记按更新时间移动到列表前方。
- 空列表状态下用户可以明确知道如何创建第一篇笔记。

### 6.3.2 创建笔记

需求：

- 列表页提供明显的新建笔记入口。
- 点击后进入空白编辑页面。
- 用户输入内容后可以保存为新笔记。
- 如果用户未输入任何内容并返回，默认不创建空笔记。

### 6.3.3 删除笔记

MVP 建议支持删除笔记。

需求：

- 用户可以从列表或编辑页删除笔记。
- 删除前需要强提醒二次确认，明确告知删除后暂不支持最近删除和恢复。
- 删除后笔记从列表移除，并同步到 CloudKit。
- MVP 暂不提供最近删除和删除后恢复能力。

后续可考虑：

- 最近删除
- 删除后恢复
- 批量删除

### 6.4 富文本编辑

### 6.4.1 编辑器技术方案

富文本编辑器使用 React + Tiptap 实现，并通过 WebView 嵌入 iOS 页面。

iOS 侧职责：

- 承载 WebView。
- 管理编辑页面导航。
- 调用 Web 编辑器获取标题和内容。
- 保存笔记数据。
- 根据键盘状态展示原生工具栏。

Web 编辑器侧职责：

- 提供 Tiptap 编辑实例。
- 管理文档内容渲染和编辑行为。
- 暴露 JSBridge 方法给 iOS 调用。
- 回传当前光标所在块、选区状态和工具激活状态。

### 6.4.2 基础编辑能力

MVP 编辑器应支持：

- 标题
- 正文段落
- 加粗
- 斜体
- 行内代码
- 一级到五级标题
- 有序列表
- 无序列表
- 任务列表
- 引用
- 分割线
- 代码块
- 表格
- 图片插入

验收标准：

- 用户可以输入和编辑文本。
- 用户可以通过工具栏切换常用格式。
- 保存后再次打开笔记，格式与内容保持一致。
- 编辑器不应因为切换页面、键盘收起或应用进入后台导致内容丢失。

### 6.4.3 标题提取

需求：

- 笔记标题优先来自编辑器文档标题。
- 如果用户没有显式输入标题，可使用正文第一行作为标题候选。
- 如果完全为空，可显示为“未命名笔记”。

### 6.4.4 自动保存

自动保存是 MVP 必选能力。用户编辑笔记时，应用应自动保存内容，避免用户依赖手动保存按钮。

自动保存需求：

- 用户输入内容后，应用在合适的防抖时间后自动保存。
- 应用进入后台前自动保存。
- 用户返回列表前自动保存。
- 自动保存不应打断编辑。
- 自动保存先写入本地数据，再进入 CloudKit 同步流程。
- 保存状态需要区分“本地已保存”和“CloudKit 已同步”。

手动保存建议：

- 编辑页可以保留保存按钮作为辅助操作。
- 用户点击保存按钮时，应立即触发一次保存。
- 即使用户不点击保存按钮，内容也应通过自动保存落盘。

验收标准：

- 用户输入内容后不点击保存，等待自动保存完成，再退出重进，内容不丢失。
- App 进入后台后重新打开，最近编辑内容不丢失。
- 用户返回列表前，当前编辑内容会被保存或进入待保存队列。
- CloudKit 不可用时，本地自动保存仍可成功。

### 6.5 日历与统计

当前代码中已经存在年历、月历和文章数量统计能力，因此产品需求保留该方向。

需求：

- 用户可以按日期查看当日创建的笔记。
- 月历中可展示每日是否有笔记。
- 年历中可展示用户长期记录情况。

验收标准：

- 某日有笔记时，日历视图有明确标记。
- 点击日期后可以查看该日期下的笔记列表。

### 6.6 搜索

MVP 建议支持本地搜索。

需求：

- 用户可以按标题搜索笔记。
- 后续支持全文搜索。
- 搜索结果按相关性或更新时间排序。

验收标准：

- 输入标题关键词后可以找到对应笔记。
- 无结果时展示空状态。

### 6.7 设置

MVP 设置页建议包含：

- 系统 Apple ID 与 CloudKit 状态。
- CloudKit 同步状态。
- 数据存储说明。
- 隐私说明。
- 打开系统 Apple ID 设置入口。

设置页需要明确说明：

- 笔记内容保存在 CloudKit。
- 产品方不保存用户笔记正文。
- 卸载应用、关闭 CloudKit 同步或删除 CloudKit 数据可能影响笔记恢复。

## 7. 数据模型

### 7.1 笔记 Article

当前基础模型：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| title | String | 笔记标题 |
| markdownText | String | 当前字段名，实际保存 Tiptap JSON 字符串；后续建议迁移为 contentJSON |
| createDate | Date | 创建时间 |
| updateDate | Date | 更新时间 |

建议后续扩展：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 全局唯一标识，便于 CloudKit 同步和冲突处理 |
| contentJSON | String | Tiptap JSON 正文，唯一正文持久化格式 |
| plainText | String | 纯文本摘要和搜索索引 |
| excerpt | String | 列表摘要 |
| attachmentRefs | [String] | 正文引用到的图片、附件等文件 ID 列表，可由 contentJSON 派生 |
| syncStatus | String | 同步状态 |
| contentVersion | Int | 内容结构版本 |

### 7.2 内容格式

编辑器内容只使用 Tiptap JSON 保存。Tiptap JSON 是笔记正文的唯一持久化格式。

原因：

- 能完整保留富文本结构。
- 适合 Tiptap 反序列化恢复编辑状态。
- 比 Markdown 更适合复杂表格、任务列表、图片等块级结构。

格式约束：

- 不保存 Markdown 副本。
- 不做 Tiptap JSON + Markdown 双格式存储。
- `plainText` 只能作为搜索、摘要、分享预览的派生字段，不作为正文持久化格式。
- 图片、附件等二进制文件不内嵌到 Tiptap JSON。
- Tiptap JSON 中只保存图片、附件等文件的引用 ID、相对路径或元数据。
- 如后续需要 Markdown 导出，应在导出时从 Tiptap JSON 临时转换，不写回正文数据模型。

### 7.3 图片与附件

图片、附件等文件也保存到 CloudKit 中，正文只保存引用。

需求：

- 图片、附件、后续可能增加的文件类型统一由附件服务管理。
- 文件保存为 CloudKit Asset，并由 CloudKit Record 管理元数据。
- Tiptap JSON 正文中只保存附件引用，不直接保存二进制内容或 base64 大字段。
- 附件引用需要能在多设备同步后重新解析到对应文件。
- 删除笔记时，应清理或标记该笔记独占的附件，避免 CloudKit 中长期残留无主文件。

建议附件引用信息：

| 字段 | 说明 |
| --- | --- |
| id | 附件唯一 ID |
| type | 文件类型，例如 image、file |
| filename | 原始文件名或展示文件名 |
| mimeType | MIME 类型 |
| assetRecordName | CloudKit 附件记录名或 CKAsset 引用 |
| size | 文件大小 |
| createdAt | 添加时间 |

## 8. 关键流程

### 8.1 首次使用流程

1. 用户打开应用。
2. 应用直接进入笔记列表。
3. 应用检查 CloudKit 可用状态。
4. 如果无笔记，展示空状态和新建入口。
5. 如果 CloudKit 不可用，展示同步状态提示，但不阻止用户使用本地笔记。

### 8.2 新建笔记流程

1. 用户在列表页点击新建。
2. 应用进入编辑页面。
3. 用户输入标题和正文。
4. 应用触发自动保存，或用户手动点击保存。
5. iOS 通过 JSBridge 获取编辑器标题和内容。
6. 应用保存 Article 数据。
7. CloudKit 在后台同步数据。
8. 用户返回列表后看到新笔记。

### 8.3 编辑已有笔记流程

1. 用户从列表点击笔记。
2. 应用进入编辑页面。
3. iOS 将已保存内容传入 Web 编辑器。
4. Web 编辑器恢复文档。
5. 用户修改内容。
6. 应用保存内容并更新 updateDate。
7. 列表按更新时间刷新。

### 8.4 离线编辑流程

1. 用户在无网络状态打开应用。
2. 应用展示本地已有笔记。
3. 用户编辑并保存。
4. 应用标记本地已保存，CloudKit 待同步。
5. 网络恢复后自动同步。
6. 同步失败时提示用户。

## 10. 隐私与安全

需求：

- 产品方不保存用户笔记正文。
- 不采集笔记内容用于分析。
- 不将笔记内容上传到自有服务器。
- 需要采集匿名崩溃和性能数据，用于提升稳定性和体验。
- 崩溃和性能数据优先接入 iOS 系统框架，例如 MetricKit 和 OSLog。
- 采集范围仅限崩溃、启动、卡顿、内存、CPU、磁盘写入、耗电等非内容类数据。
- 不采集正文、标题、图片、附件内容、剪贴板内容或用户输入原文。
- 匿名诊断数据应在设置页提供说明，后续可提供关闭选项。
- 图片、附件等内容也应存储在 CloudKit 中，正文只保存引用。

隐私说明中应明确：

- App 不提供自有账号系统，也不接入 Sign in with Apple 登录流程。
- 数据同步依赖系统层 Apple ID 和 CloudKit。
- 用户可以通过 Apple 系统设置管理 Apple ID 与 CloudKit 同步能力。
- 匿名崩溃和性能数据仅用于稳定性分析，不用于分析笔记内容。

## 11. 崩溃与性能诊断

MVP 需要采集匿名崩溃和性能数据，优先使用 iOS 系统框架。

建议方案：

| 能力 | 推荐框架 | 说明 |
| --- | --- | --- |
| 崩溃诊断 | MetricKit | 接收系统提供的 crash diagnostics |
| 性能指标 | MetricKit | 接收启动、响应、CPU、内存、磁盘、耗电等系统指标 |
| 结构化日志 | OSLog | 记录非内容类运行状态，便于本机调试和问题定位 |
| 性能埋点 | OSLog Signpost | 标记编辑器加载、保存、CloudKit 同步等关键耗时 |

采集边界：

- 可以采集 App 版本、iOS 版本、设备型号、崩溃类型、性能指标、功能模块名。
- 可以采集编辑器加载耗时、自动保存耗时、CloudKit 同步状态码。
- 不采集笔记正文、标题、图片内容、附件内容、用户输入原文。
- 日志中涉及用户数据的字段默认使用隐私脱敏或不记录。

验收标准：

- App 可以接收并处理 MetricKit 的诊断和性能 payload。
- 关键链路有 OSLog 分类，例如 editor、storage、icloud、bridge。
- 诊断数据不包含笔记正文和附件内容。
- 设置页隐私说明中包含匿名诊断数据说明。

## 12. 性能要求

- 应用冷启动后应尽快进入可操作状态。
- 笔记列表滚动应流畅。
- 打开普通笔记时编辑器应在可接受时间内完成渲染。
- 保存操作不应长时间阻塞主线程。
- 大文档编辑时应避免频繁全量序列化导致卡顿。

建议指标：

- 普通笔记打开时间小于 1 秒。
- 保存反馈小于 300 毫秒。
- 列表滚动保持 60 FPS。

## 13. 异常状态

需要覆盖以下异常：

- 系统 Apple ID 未登录。
- CloudKit 不可用。
- CloudKit 空间不足。
- CloudKit 同步冲突。
- Web 编辑器加载失败。
- JSBridge 调用超时。
- 保存失败。
- 图片插入失败。

异常提示原则：

- 说明当前发生了什么。
- 告诉用户是否影响数据安全。
- 给出可执行操作，例如重试、稍后同步、打开系统设置。

### 14.1 必须完成

- 免登录进入应用。
- CloudKit 数据存储。
- 笔记列表。
- 新建笔记。
- 编辑笔记。
- 保存笔记。
- 自动保存。
- React + Tiptap 富文本编辑器嵌入 iOS。
- 基础格式工具栏。
- 基础同步状态提示。

### 14.2 应尽量完成

- 删除笔记。
- 本地搜索标题。
